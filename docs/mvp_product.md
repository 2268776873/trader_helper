# Windows MVP 产品要求

## 产品定位

第一版是“低频仓位管理决策助手”，不是自动交易客户端。程序负责取数、校验、计算和留痕，用户负责核对并在券商客户端手工下单。

## 主界面

主界面需要同时回答四个问题：

1. 当前数据是否可信；
2. 策略处于什么状态；
3. 为什么建议买、卖或不操作；
4. 如果执行，合法价格和数量是多少。

### 数据确认区

每个标的显示：

| 字段 | 内容 |
|---|---|
| ETF代码和名称 | 防止标的映射错误 |
| 最新价、买一、卖一 | 显示价格及盘口 |
| IOPV/参考净值 | 显示数值、来源和更新时间 |
| 折溢价 | 同时显示公式输入和计算结果 |
| 指数收盘、汇率 | 显示值、数据日期和来源 |
| 250日高点、当前回撤 | 显示计算口径 |
| 持仓、市值、当前权重 | 显示账户输入时间 |
| 数据状态 | 正常、需复核、已阻断 |

任何自动数据都必须能看到：

- 来源名称；
- 上游类别；
- 原始时间戳；
- 本地取得时间；
- 是否来自缓存；
- 与其他来源的偏差；
- 是否参与最终计算。

### 多源一致性区

同一字段以来源表格展示：

| 字段 | 来源A | 来源B | 偏差 | 判定 |
|---|---:|---:|---:|---|
| 卖一价 | 2.040 | 2.041 | 0.049% | 通过 |
| IOPV | 1.900 | 1.918 | 0.947% | 通过 |

“独立来源”按上游数据链路判断。两个网页如果复用同一个行情供应商，只计作一个来源。

默认阈值：

- ETF盘口价差异不超过一个最小价格变动单位；
- 两个估值计算出的溢价差不超过1个百分点；
- 任何参与决策的盘中数据不超过5分钟；
- 日期不符合策略预期时阻断，不自动沿用上一期数据。

### 决策建议区

建议卡片至少显示：

```text
结论：建议买入 / 建议卖出 / 今日不操作 / 数据不足
触发原因：基础建仓 / 回撤档位 / 再平衡
建议金额：
建议数量：
最高买入价或最低卖出价：
预计成交金额：
买卖后权重：
买卖后现金：
触发档位：
未满足条件：
```

界面必须区分：

- `候选建议`：策略条件满足，但数据或账户信息尚未确认；
- `可执行建议`：数据检查和账户检查全部通过；
- `已确认执行`：用户确认已在券商下单；
- `已成交`：用户录入或导入成交回报。

### 状态机区

按资产展示基础建仓和回撤档位状态：

| 状态 | 含义 |
|---|---|
| `ARMED` | 尚未达到回撤阈值 |
| `TRIGGERED` | 回撤已触发，等待溢价或其他条件 |
| `READY_TO_REVIEW` | 条件满足，等待用户核对 |
| `ORDER_CONFIRMED` | 用户确认已手工下单 |
| `PARTIALLY_FILLED` | 部分成交，仍有剩余金额 |
| `FILLED` | 本周期档位完成 |
| `BLOCKED` | 数据、现金、权重或交易状态阻断 |
| `DISABLED` | 用户人工关闭 |

每次状态变化显示时间和原因。例如：

```text
SP_L1
ARMED → TRIGGERED
2026-07-30 08:35
原因：人民币参考值回撤达到9.20%，阈值为8.00%

TRIGGERED → BLOCKED
2026-07-30 14:02
原因：缺少第二个独立IOPV来源
```

## 用户确认流程

生成可执行建议前要求用户逐项确认：

- 标的和ETF名称正确；
- 券商卖一价与程序差异在允许范围内；
- 券商IOPV/参考净值已录入或与程序一致；
- 持仓份额、可用现金和未成交委托正确；
- 建议价格、数量、买后权重和剩余现金已查看。

确认操作只表示“用户已阅读建议”，不能被程序视为真实成交。档位状态只能根据用户录入或导入的成交回报更新。

## 日志与可追溯性

每次决策保存：

- 原始数据快照；
- 数据来源和质量检查结果；
- 策略参数版本；
- 状态机变更；
- 计算中间值；
- 最终建议；
- 用户确认与成交记录。

日志不保存券商密码、验证码或完整资金账号。

## 用户数据更新接口

客户端同时支持两种更新方式：

### Excel导入/导出

适合初始化账户、批量补历史交易、定期对账和备份。标准模板为：

`outputs/account_template/trade_helper_account_template.xlsx`

导入时按工作表名和英文列名匹配，不依赖列位置。客户端先执行预检查并展示新增、更新、重复和错误行；用户确认后再写入本地数据库。任何一行失败时，不得部分写入同一批次。

### APP表单

适合日常少量更新：

- 更新账户快照；
- 更新三只ETF持仓；
- 录入一次成交；
- 录入资金转入、转出、分红或利息；
- 在14:00录入券商卖一价、IOPV和未成交委托；
- 确认或撤销一条建议。

推荐内部接口：

| 接口 | 用途 |
|---|---|
| `POST /api/account-snapshots` | 新增账户快照 |
| `POST /api/position-snapshots` | 新增持仓快照 |
| `POST /api/trades` | 新增或更正成交 |
| `POST /api/cash-flows` | 新增资金流水 |
| `POST /api/manual-market-checks` | 提交盘中券商复核数据 |
| `POST /api/imports/excel/validate` | 只校验Excel，不写入 |
| `POST /api/imports/excel/commit` | 用户确认后原子导入 |
| `GET /api/exports/account-data.xlsx` | 导出完整账户数据 |

第一版可以在Windows客户端内部实现同样的数据服务，不需要开放网络端口。以后如果增加手机端或Web端，再保持字段兼容地开放HTTP接口。
